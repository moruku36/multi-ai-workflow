# OpenClaw 構築メモ：権限境界と検証の進め方

2026-11-05 時点の途中経過。別の環境で再現するための判断材料であり、完成済みのインストール手順ではありません。構成やコマンドはバージョンで変わるため、実行前に対象版の公式資料と自分の環境を確認してください。以下の事例は作業中の会話・提示された実行結果に基づく報告で、独立した再試験ではありません。

## この事例で確認・報告されたこと

- Mac mini 上の Gateway と CLI は 2026.10.9 から **2026.10.10** に更新され、両方のバージョン、Gateway 稼働、接続チェック成功が報告された。Gateway は loopback 待受けと表示され、Windows から SSH 転送でアクセスした。これは Gateway の外部公開と、SSH の通信が物理的にどの経路を通るかを別々に考える必要があることを示す。
- 更新前に対象版の確認と dry-run を行い、目立った警告は検出されなかった。dry-run の成功は更新後の各機能の動作確認ではない。
- サンドボックスとブラウザーの Docker イメージのビルド成功が報告された。イメージのビルド成功だけでは、ブラウザー起動、画面接続、操作、隔離の検証は完了しない。
- OpenShell プラグインの導入と Gateway への反映、および別ホスト上で専用 workspace の作成が報告された。プラグイン導入や workspace 作成だけでは、OpenClaw の実タスクが意図した制約下で実行されたことを示さない。
- エージェント間の一方向通知はコード反映と通知設定の切り替えが報告されたが、新着イベントでの受信は未確認。逆方向も準備中だった。どちらも一連の配送成功とは扱わない。

## 構築の順序と境界

1. **Gateway と管理経路を分ける。** まず待受けアドレス、認証、SSH 転送の終点と接続先を確認する。loopback は待受けの範囲を限定するが、ホストに侵入したプロセスへの防御や転送経路全体の保証ではない。公開先やポート、トークンを共有文書に貼らない。
2. **Docker の権限を別途評価する。** Gateway が Docker の管理口を使える場合、専用ブラウザー以外のコンテナーも操作できる可能性がある。ブラウザーを専用コンテナーにしても、Docker ソケットの管理権限が専用コンテナーだけに限定されるとは限らない。ホストのファイル、ネットワーク、他のコンテナー、権限昇格への影響を確認し、実際に必要な範囲だけ許可する。
3. **ブラウザーの独立性を実測する。** イメージ、永続プロファイル、画面接続、認証情報、外向き通信と終了後の残存データを確認する。画面用の認証情報が生成される場合は安全に保存し、ログや会話に値を出さない。テスト用の無害なページで起動・接続・操作・終了を別々に確認する。
4. **OpenShell を使う場合は実行経路を検証する。** どのホストのどのユーザー・workspace で実行され、ファイル、ネットワーク、認証情報に何が許可されるかを確認する。無害な許可・拒否テストと監査結果を記録し、プラグインの存在を隔離の証明にしない。
5. **ラウンジ通信は方向ごとに試験する。** 送信、イベント発生、受信、重複・再試行、権限不足時の失敗を無害なメッセージで確認する。設定反映、通知受信、相手の処理完了は別の状態として記録する。公開ガイドには非公開リポジトリの内容を載せない。

## GitHub と認証情報

GitHub の CLI や Git が利用可能なこと、ログイン済みであること、対象リポジトリに必要な権限があることはそれぞれ別です。対象と読み書き範囲を決め、まず読み取りを検証し、書き込みは指定したブランチや PR で確認します。トークンをコマンド出力・ログ・プロンプトに含めず、必要以上のリポジトリや権限を与えません。コンテナーへの Git 導入やイメージ再作成時は、作業領域のバックアップと復元確認を先に行います。

**1Password を使うだけで秘密がエージェントから見えなくなるわけではありません。** CLI、スキル、プラグインや環境変数への注入は、権限と使い方によって秘密値をプロセスやその出力に渡し得ます。秘密値を見せずに操作したい場合は、対象サービスごとに、代理実行・署名など候補方式の実際の権限、エージェントが操作できる範囲、ログや結果への漏出、失効方法を検証してください。名称だけで安全と判断せず、最小権限の専用資格情報と人による承認を検討します。この事例では 1Password 連携方式の選定・設定・権限付与は未完了です。

## 更新とバックアップ

更新前に現行版・対象版・リリース情報・プラグイン互換性と実行中タスクを確認し、停止による影響と復旧手順を決めます。設定と作業データの対象範囲を明確にしてバックアップし、検証と別環境での復元試験を行います。バックアップには秘密が含まれ得るため、保管先・アクセス権・保持期間を管理します。更新後は CLI と Gateway の版・稼働・接続に加え、各チャネル、サンドボックス、ブラウザー、通知を個別に確認します。バックアップの作成、整合性検証、復元成功は別の証拠です。
