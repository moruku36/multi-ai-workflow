# 品質ラッパーへの任意静的チェック接続

[English](quality-wrapper-integration-2026-11-05.md) | [日本語](quality-wrapper-integration-2026-11-05.ja.md)

## オフラインで実装した内容

既存 `tools/check_quality.py` に、明示した `--static-target` と任意の `--static-tool` を追加しました。新しいフラグなしでは静的エンジンを実行せず、従来の合否判定を維持します。従来検査のPASSをRuff/Semgrepの完了とは扱いません。

指定時だけ、検証済みの単独アダプタを1回呼びます。その報告、対象ハッシュ、指摘、状態、上限を `results.selected_static_checks` に含めます。指摘あり、未導入、不完全出力、時間超過、例外、不正・空の成功報告は全体をFAILにします。静的検査のPASSで既存検査の失敗を隠しません。Ruff書式検査、非選択のエンジン、選択外ファイルは未検証として明示します。

```sh
python tools/check_quality.py --json --static-target tools/run_static_checks.py --static-tool ruff --static-tool semgrep
```

対象はラッパー自身のリポジトリからの相対パスです。別の試験リポジトリには単独アダプタを使います。常駐、CI、横展開、認証、設定変更は含みません。従来検査は `py_compile` により `__pycache__` を作る場合がありますが、静的アダプタ自身は引き続き一時コピーを修正なしで検査します。

## 再利用するときの手順

1. 利用が認められた完全なcheckoutで、現在のheadを確認します。検証基準は `8a0877ab5225cbb806389e1a19842bbce71a47e3` です。公開準備時にもGitHubのmainと一致することを確認しました。
2. この変更が適用済みかを確認し、未適用のcheckoutにだけ差分を適用します。パッチを使う場合は先に `git apply --check` を行い、衝突時は新しい作業を上書きせず整合させます。
3. 利用承認済みのRuff 0.17.3 / Semgrep CE 1.183.0を、対象リポジトリ外の実行パスから利用します。以前の合成2ファイルの受入範囲は、単独アダプタの文書に記録しています。新しい環境にも導入済みだとは推定しません。
4. 完全なcheckoutで上記コマンドを1回実行し、JSONと正確なheadを残します。限定スナップショットに必須の既存テスト群が欠けていればFAILのままとし、成功表示のために必須検査を外しません。
5. 実指摘を確認し、試験リポジトリの範囲を決めます。Alibaba OCR統合、Direct MiMo復元、Cloudflare focused audit、P2/P4の通信受入は、このP1ゲートとは分けて進めます。
