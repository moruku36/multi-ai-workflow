# エージェントのKVキャッシュ制御：将来の検証案

**状態：提案・未実装。** 現行のmulti-ai-workflowがAKVを使っている、費用削減を達成した、または任意のプロバイダーAPIでKV操作できるという記録ではない。

## 根拠と適用範囲

[Cache Engineering for Agents（arXiv:2610.28577v1）](https://arxiv.org/html/2610.28577v1) は、テキスト履歴を編集せずにKVキャッシュへの`drop`と`repos`を指示する方式を提案する。著者の実験結果と確認範囲は別リポジトリに追加予定の日本語サーベイにまとめる。著者コードや当リポジトリへの移植は検証していない。

適用候補は長時間のツール反復と、自前で制御できる推論サーバーである。プロバイダーAPIのプロンプトキャッシュ、会話要約、AKVの直接KV制御を別の機能として扱う。既存の[MiMo効率化改善案](reports/2026-10-19-mimo-efficiency-review.ja.md)のキャッシュヒット率の仮説とも測定対象を分ける。

## 段階的な検討

1. 推論バックエンドのcapabilityとAPI仕様を記録する。KV操作非対応なら現行方式を維持する。AKVの「互換API」を任意の既存APIでKV操作可能という意味にしない。
2. テキスト軌跡とキャッシュ操作ログを別管理し、モデル、テナント、操作履歴で状態を分離する。エージェント間の無条件共有は行わない。
3. 同じタスク集合、予算、停止条件で、全文保持、要約、rolling-dropを比較する。成功率、実請求額またはGPU時間、KVメモリ、P95要求遅延、復元時の正しさを記録する。
4. 費用削減に加え品質の非劣化を採用条件にする。古い制約の参照、枝分かれ、再試行、プロセス再起動を回帰試験の候補にする。

## 最初の無料確認と判断点

公開軌跡の履歴長・削除候補・操作順序を整理し、模擬状態機械で同一トークン列と異なる操作履歴の取り違えを試す。これはGPU性能の再現ではない。必要なバックエンド、実験費用、データ分離、品質基準が定まるまでは実装採用と記録しない。
